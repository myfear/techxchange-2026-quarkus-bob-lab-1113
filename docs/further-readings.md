# Further Readings

Extend the lab's IBM Bob and Quarkus workflow with these articles from The Main Thread. Article and collection links open in a new tab or window.

## IBM Bob

### [IBM Bob Cost Control Starts With Context Hygiene](https://www.the-main-thread.com/p/ibm-bob-cost-guide){ target="_blank" rel="noopener noreferrer" }

Learn how to keep Bob focused with `.bobignore`, precise file references, and smaller MCP tool selections. The article also explains when to start a fresh chat and how to compare context usage with Bobcoin spending.

### [IBM Bob 2.0 with Engram: Persistent Project Memory](https://www.the-main-thread.com/p/ibm-bob-engram-durable-project-memory){ target="_blank" rel="noopener noreferrer" }

Connect Bob to Engram through MCP to store project decisions in a local knowledge graph. Learn how project rules guide recall across fresh tasks and how the IDE's graph view relates to the agent's tools.

### [IBM Bob Lifecycle Hooks for Agentic Development](https://www.the-main-thread.com/p/ibm-bob-lifecycle-hooks-agentic-development){ target="_blank" rel="noopener noreferrer" }

Configure lifecycle hooks to supply repository context, reject selected file edits, and record test results. Learn which hooks can block actions and where verification still belongs in CI.

## Quarkus

### [Why Quarkus Agent Skills Matter More Than Another Model Upgrade](https://www.the-main-thread.com/p/quarkus-agent-skills-roi){ target="_blank" rel="noopener noreferrer" }

See how Quarkus Agent MCP supplies extension-specific guidance and why this matters when generated applications combine several extensions. The article examines successful and failed runs to explain the value and limits of framework skills.

### [Building a Quarkus Testing Strategy That Reflects Real Production Risk](https://www.the-main-thread.com/p/quarkus-testing-reading-path){ target="_blank" rel="noopener noreferrer" }

Learn how to choose between application tests, tests of the packaged service, API contract checks, and browser tests. This reading path helps you extend the lab's HTTP checks into a test strategy based on likely failures.

### [Quarkus JAR Tree Shaking: Trim Dead Weight From JVM Builds](https://www.the-main-thread.com/p/quarkus-jar-tree-shaking){ target="_blank" rel="noopener noreferrer" }

Measure the effect of removing unreachable dependency classes from a packaged JVM application. Learn how to compare artifact sizes, interpret tree-shaking reports, and account for dynamically loaded classes before using the result in a container.
